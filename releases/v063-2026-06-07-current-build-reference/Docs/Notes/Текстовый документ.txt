 Детали ошибки
В Python (эталон):

python
d = s.offsets[lb-1] - s.offsets[lb]
if d < -CELL_SIZE or d >= DM3_OFFSET_GAP_MAX: break
В ассемблере (VDC.asm, метка .dm3_l):

asm
LD   A, C          ; off[lb-1]
SUB  B             ; A = off[lb-1] - off[lb]
NEG                ; A = off[lb] - off[lb-1]
ADD  A, VDC_CELL_SIZE
CP   VDC_CELL_SIZE + VDC_DM3_OFFSET_GAP_MAX
JR   NC, .dm3_l_done
Анализ:

Входная разность d = off[lb-1] - off[lb].

После NEG → -d = off[lb] - off[lb-1].

Прибавляем CELL_SIZE → CELL_SIZE - d.

Сравниваем с CELL_SIZE + GAP_MAX.

Поскольку CELL_SIZE - d ≤ CELL_SIZE < CELL_SIZE + GAP_MAX, условие CP всегда даёт CF = 1 (A < операнда), и JR NC (переход, если CF = 0) никогда не срабатывает.

Следствие: даже при d ≥ GAP_MAX (шары уже далеко раздвинуты) цикл продолжается → match‑3 не прерывается и может быть ложно найден для несоприкасающихся шаров. Фактически проверка gap мертва, что приводит к неправильному распознаванию цепочек.

✅ Как должно быть правильно
Нужно сравнивать исходную разность d с -CELL_SIZE и GAP_MAX. Исправленная реализация (для левой части):

asm
; off[lb-1] в A, off[lb] в B
LD   A, C          ; off[lb-1]
SUB  B             ; A = off[lb-1] - off[lb]
CP   -VDC_CELL_SIZE
JR   C, .dm3_l_done   ; d < -CELL_SIZE → break
CP   VDC_DM3_OFFSET_GAP_MAX
JR   NC, .dm3_l_done  ; d >= GAP_MAX → break
Аналогично для правой части (.dm3_r), где сравнивается d = off[lb] - off[lb+1].

## 🚨 Критическое несоответствие (Match‑3 никогда не работает со смещениями)

### Описание
В `VDC.asm`, процедура `VDC_DetectMatch3`, левый и правый циклы проверки gap-условия между соседними шарами реализованы с ошибкой, которая **полностью отключает проверку** и позволяет ошибочно находить match‑3 даже при больших смещениях.

### Python-эталон (верно)
```python
d = s.offsets[lb-1] - s.offsets[lb]
if d < -CELL_SIZE or d >= DM3_OFFSET_GAP_MAX:
    break
ASM (неверно)
asm
; off[lb-1] в C, off[lb] в B
LD   A, C
SUB  B
NEG                ; A = off[lb] - off[lb-1]
ADD  A, VDC_CELL_SIZE
CP   VDC_CELL_SIZE + VDC_DM3_OFFSET_GAP_MAX
JR   NC, .dm3_l_done   ; этот переход НИКОГДА не выполняется
Анализ:

После NEG и сложения с CELL_SIZE получается CELL_SIZE - (off[lb-1] - off[lb]).

Это значение всегда меньше CELL_SIZE + GAP_MAX, так как GAP_MAX >= 1.

Сравнение CP даёт CF = 1 (A меньше операнда), переход JR NC не срабатывает.

Следовательно, условие d >= GAP_MAX никогда не останавливает цикл.

Последствия:

Матчи распознаются даже для шаров, которые физически разъединены (gap > 10).

Цепочка может удалять неправильные группы, что разрушает игровую логику.

Особенно заметно при вставке нового шара (InsertAt) – он сразу может вызвать ложный match.

Исправление
Заменить код на прямой анализ разности d:

asm
LD   A, C          ; off[lb-1]
SUB  B             ; d = off[lb-1] - off[lb]
CP   -VDC_CELL_SIZE
JR   C, .dm3_l_done   ; d < -CELL_SIZE → break
CP   VDC_DM3_OFFSET_GAP_MAX
JR   NC, .dm3_l_done  ; d >= GAP_MAX → break
Аналогично для правой части (.dm3_r), где d = off[rb] - off[rb+1].
